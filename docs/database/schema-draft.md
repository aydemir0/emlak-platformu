# PostgreSQL-near schema draft

## Scope and notation

This is a non-executable column catalog for the 45-table model. It intentionally contains no DDL, migration, RLS policy, provider type, or runtime scaffold. See [Domain model](domain-model.md), [Entity catalog](entity-catalog.md), [Relationships](relationships.md), and [ERD](erd.md).

- `NN` = not null; `NULL` = nullable. `now()` is a proposed database default for immutable creation/occurrence timestamps only.
- UUID aggregate IDs are generated by one documented database/server strategy during implementation. The draft does not choose the function.
- Every FK uses `ON UPDATE RESTRICT`. Hard-delete behavior is `RESTRICT` unless [Relationships](relationships.md) explicitly permits cascade during an authorized purge.
- `currency_code` checks `^[A-Z]{3}$`; all money amounts are `bigint` minor units and non-negative unless a signed amount is explicitly noted.
- Mutable aggregate metadata row abbreviates four actual columns: `created_at timestamptz NN default now()`, `updated_at timestamptz NN default now()`, `version bigint NN default 1 check > 0`, `deleted_at timestamptz NULL`. `updated_at` changes explicitly on writes; it has no clock default beyond creation.
- Audit actor FKs are nullable where system/anonymous actions are valid. Free text and `jsonb` are length/size bounded by server validation and implementation checks.

### `property_customer_matches`

`id uuid` NN PK; `property_id uuid` NN FK; `customer_id uuid` NN; `customer_request_id uuid` NN; composite FK `(customer_request_id,customer_id)` to `customer_requests(id,customer_id)`; `rule_version text` NN; `property_version bigint` NN check > 0; `request_version bigint` NN check > 0; `basis_fingerprint text` NN checked fixed safe hash format; `status text` NN default `PROPOSED` checked `PROPOSED/REVIEWED/DISMISSED/STALE`; `source text` NN checked `MANUAL/RULES/ASSISTED`; `score numeric(7,6)` NULL check between 0 and 1; `generated_at timestamptz` NN; `reviewed_at timestamptz` NULL; `reviewed_by_user_identity_id uuid` NULL FK; standard mutable metadata. Permanent unique `(property_id,customer_id,customer_request_id,rule_version,property_version,request_version,basis_fingerprint)` makes an identical generation idempotent; partial unique `(property_id,customer_id,customer_request_id)` where status is `PROPOSED` or `REVIEWED` permits only one current nonterminal generation. Completion locks property, request, and current matches in the documented order, verifies parent versions under lock, then retires/inserts match and reasons atomically. Every match-input-changing parent mutation marks affected current rows `STALE` in its parent transaction, so a stale worker fails/no-ops and cannot leave an obsolete current generation. Indexes `(customer_request_id,status,score desc)` and `(property_id,status)`. The composite FK prevents attaching a request to a different customer; lifecycle is proposed pending product approval.

## Constraint and index implementation notes

- Partial uniqueness involving “active” or “current” rows is an index design, not a plain unique constraint. Exact predicates must be migration-reviewed.
- `current_slug` and `current_route_reservation_id` are paired on each current-route aggregate. Slug history has no current row.
- A mandatory deferred constraint trigger validates at commit that every route reservation is referenced by exactly one matching owner family across the four current aggregates or four retired-history tables; `route_kind` and `retired_at` must agree with that reference. Ordinary per-table unique FKs alone are insufficient.
- Cross-row rules such as feature value-kind compatibility, exactly one history-table owner per retired route reservation, and “one cover image” require transaction-level domain validation plus a reviewed deferred constraint/trigger only if PostgreSQL enforcement materially improves safety.
- RLS policies, grants, full-text/spatial indexes, partitioning, exclusion constraints, and retention jobs are intentionally deferred until the access matrix and measured query/legal requirements are approved.
- No index is proposed for every theoretical property/filter combination. Curated query definitions bound indexable and performance-critical paths.
